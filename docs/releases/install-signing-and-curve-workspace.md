## OPPO 安装提示的核查

用户反馈OPPO X9U从GitHub下载v0.1.3及最新版时提示“解析失败：安装包没有签名文件”。本次直接读取GitHub的Release资产记录、下载两份原包，并核对完整SHA-256：

| 发布附件 | 大小（字节） | SHA-256 | V2 | JAR签名文件 / V3 |
| --- | ---: | --- | --- | --- |
| SpektraLab-Android-v0.1.3-universal.apk | 54949934 | 9dd783c5104acef845674376610bf2137e47120f51bdb6f7a78eb0dfbce8d894 | 验证通过 | 无 / 无 |
| Theia-v0.1.4-universal.apk | 55100678 | 3eb20842635ae82840477c2d6a3fec900ae8712c50d6454a8ec11ce08851d2a7 | 验证通过 | 无 / 无 |

两个文件与GitHub资产摘要一致，并非服务器附件完全没有签名；但都缺少META-INF下的JAR证书，只有V2。这是本次确认并补齐的安装兼容缺口。没有取得OPPO上的实际文件和PackageInstaller日志，不能断言具体ColorOS版本一定要求V1，也不能证明手机最终下载到的文件与本次校验文件相同。

Gradle的release signingConfig现在显式启用V1、V2、V3，继续使用原证书：

    3df31b6b60a0e7edb705d495c086e28cb699883d1b29ceb723992b08ed43af39

新增 tools/verify_release_apk.py，交付前执行：

    python tools/verify_release_apk.py app/build/outputs/apk/release/app-release.apk --json release-verification.json

校验包括ZIP完整性、实际JAR证书、单独V1验证、V2/V3验证、原证书指纹、包名、版本及最终文件SHA-256。默认minSdk26时，apksigner可能选择现代方案而报告V1未使用；工具额外以API21—23的范围检查JAR路径。这只是密码学校验，不代表应用支持低于Android 8的系统；minSdk没有降低。签名后只做逐字节复制，不重新压缩APK。

在独立空白API37模拟器完成GitHub v0.1.3安装、覆盖到v0.1.4、再覆盖安装新原签名包并启动，均成功；这是标准Android安装/升级验证，不等于已在OPPO厂商安装器实测。原测试模拟器数据未清空。

## 大图优先的曲线工作区

参考Darkroom的照片优先、工具集中和辅助控制点思路，沿用Theia圆体、炭灰与琥珀主题，没有复制外部图片资产。

- 手机取消旧的24%高度/最高180dp预览限制，照片占剩余主要空间并铺满可用宽度；底部固定曲线工具。宽屏为左侧大图、右侧紧凑工具，右栏限制在300—380dp。
- 精调在曲线区内切换，输入/输出滑杆出现时照片大小不变；另有大图查看，返回后保留通道和选点状态。
- 五通道入口固定可见；阴影、中间调和高光显示辅助圆点，可直接一拖建立并调整控制点。未使用的圆点跟随曲线，仅在操作时写入模型，打开工作区不会偷偷增加点或改变照片。
- 放大控制点的命中范围并保留抓取偏移，减少手指落下后跳点。空白滑动不建点，轻点仍可添加，取消/多指/退出仍恢复本次手势起点。
- 曲线后显示已有RGB分布信息，不再次读取整图或重跑引擎；照片上的重复直方图在此工作区隐藏。
- 顶部撤销/重做，底部选点值、删除、精调和复位菜单；底部单独预留系统导航区域，避免按钮贴住手势条。按住原图仍复用缓存源图。

曲线插值、端点约束、五通道模型、导出精度、胶片/相纸及原渲染优化均保持。0—255只是控件读数，未把底层浮点曲线量化到8位。
