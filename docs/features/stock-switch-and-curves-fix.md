# 胶片切换性能与曲线交互修复

日期：2026-11-11。基线为 v0.1.4 / 441305c。本批是缺陷修复，不推进 T06 或宣称完成尚未开发的工作包。

## 复现与原因

1600×1067 的同一 RGBA16 输入，未启用新曲线/HSL 时，Grade 的逐像素参考路径反复调用 ToneCurves.isIdentity 和 ColorAdjustments.isNeutral。原来的 getter 每次遍历列表并创建迭代器；五次中性预览转换累计约 2.6GB 托管分配、312 次 GC。这个数是累计分配，不是驻留或活跃峰值。

1600×1200 实际开片后，四款彩色胶片各切换三轮，基线一次切换中位数约 1.64—1.65 秒，native 渲染通常约 90ms；主要回退在应用侧预览转换，而非新增的胶片光谱计算。

## 修复

- 在不可变 ToneCurve、ToneCurves 与 ColorAdjustments 构造时计算中性标志，像素循环只读布尔值。没有改插值、色彩公式、编码、预览尺寸或导出质量设置。
- 取消过期转换时逐条带检查，并回收尚未发布的 Bitmap；保持最新请求落地。
- 待转换底图保存在私有状态中，供更新的后期编辑复用；公开 lastResult 与对应画面一起就绪，防止旧调色覆盖和导出前后的画面跳变。
- 预览保存记录与主线程编辑保持顺序，避免 120ms 去抖任务把较旧的后期快照写回 sidecar。
- 相同或不存在的材料不启动渲染；导入/导出忙碌时拒绝修改材料。兼容相纸仍按原规则配对。
- 点击已经可见的胶片不再强制动画滚动整个材料条。

旧版专项已复现“胶片渲染覆盖最新后期”的失败。修复过程还由既有导出断言捕捉到一次公开底图提前就绪的问题，改用私有待转换状态解决，保留原断言，没有将其删掉或放宽。

## 曲线工作区

主调色页在基础影调之后只保留“编辑曲线”入口，不把可拖动图表放在日常参数滚动路径中。专用工作区保留现有照片预览、按住原图和直方图：手机竖屏上下排列，横屏和平板左右排列，完成/关闭操作固定在顶部。

轻点空白在松手后添加控制点，拖动已有点才修改曲线；空白滑动允许滚动，不在按下时先加点。点间距不足或已到数量上限时，不再把空白拖动转成最近控制点的移动。取消/离开恢复当前手势，已提交的编辑保留。精细滑杆沿用细轨与圆点。

## 测量口径

API 37 x86_64 模拟器，同一 Release native 二进制、同一尺寸和参数；两轮 before/after 交错，每种预览先预热，再取五次转换的中位数。材料切换每轮十二次。颗粒/眩光关闭用于可重复的切换测量；默认效果开关没有修改。

| 项目 | 原版两轮 | 首次修复两轮 |
| --- | --- | --- |
| 中性预览转换 | 1355 / 1368ms | 60 / 57ms |
| 基础影调预览转换 | 1467 / 1510ms | 141 / 156ms |
| 已启用曲线的预览对照 | 81 / 71ms | 74 / 85ms |
| 胶片切换中位数 | 1652 / 1636ms | 366 / 366ms |
| 三次快速切换后落地 | 1666 / 1648ms | 421 / 431ms |

四轮三种预览的整图像素摘要一致，尺寸相同。已启用曲线的对照走原生路径，数据有运行抖动，不能把它包装成曲线内核加速。本轮不增加 GPU 内核，不改变 native/材料资源。最终原片回归、导出文件哈希与界面证据另行核对。

这些是模拟器测量，不是小米 17 Pro 真机承诺；大图全局活跃峰值问题仍属 F03，不能将本次减少临时分配等同于已解决所有 RAW 内存上限。

## 最终验收

同一生产APK完成26组回归、178条测试记录。手机大字体、平板和横屏的完整曲线操作、撤销/重做、按住原图及三格式输出全部通过并核对截图。后续对触摸输入隔离、撤销预期和双向滚动的修正仅修改测试，生产APK逐字节相同。

最终构建的中性预览中位数62ms，实际胶片切换中位数356ms。全部测量轮次的三个预览像素摘要相同；原生库及引擎资源与v0.1.4安装包逐项字节一致。24MP真实NEF的中性/曲线/HSL三组全尺寸TIFF保持6064×4040，并保持既有完整SHA-256，未降低导出质量或关闭默认效果换速度。

原签名本地修复包仍为0.1.4（5），未自动提交或发布。详细当前范围与剩余项见开发进度。
