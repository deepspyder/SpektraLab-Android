# F07 第二批：原片校验、重新关联与工作台恢复

日期：2026-11-13。范围为默认编辑记录的来源恢复和工作台引用持久化；F07 整体仍为进行中。

## 使用流程

图库每张照片右侧的原片菜单提供“核对原片”和“重新关联原片”。首次核对有明确说明：校验凭据从当前文件建立，不能追溯证明核对之前的文件内容。操作读取完整文件，可取消，不复制原图或进行 RAW 显影。

已核对的照片显示状态，之后从图库打开时会复核原片。文件移动后，通过 Android 文件选择器指定新位置；只有完整 SHA256 和字节数同时相同才允许关联。文件名、拍摄尺寸或媒体编号相同均不足以通过。已有图库记录或工作台中的另一项不会被合并、覆盖。缺乏校验凭据时，只能重新授权相同 URI，不能猜测另一个地址的原片。

图库顶部提供“恢复工作台”，显示保存的照片数和导出勾选数。保存并恢复照片顺序、当前照片及导出勾选，包括空勾选和暂时离线的照片。启动不主动恢复或解码整组照片，用户点击后只打开当前一张。每张照片的已提交调整仍由正式编辑库保存；未提交手势及跨重启的撤销历史不属于本批持久化范围。

## 数据与并发

生产数据库从 v1 事务升级到 v2，增加 `source_checks`、`retired_sources` 和 `workbench`，保留原资产、默认编辑版本、revision、参数原文和备份。T06 沙盒数据库仍独立。

重新关联校验当前资产 ID、原 URI 和编辑 revision，在同一事务内更新位置、旧地址标记及工作台引用。参数、资产 ID、默认编辑版本 ID 和编辑 revision 不变。旧地址标记阻止迟到的保存、批量应用或旧 sidecar 再次认领；旧工作台快照会规范到当前地址。事务前后中断的结果必须分别是完整回滚或完整关联，不允许地址与工作台只更新一半。

工作台结构变化通过有界的合并队列在 IO 线程串行保存；调参不写工作台。跨 ViewModel 的代次保护阻止旧实例的迟到写入覆盖新工作台。选择器返回优先于恢复到前台时的元数据刷新；提交期间完成必要的内存引用更新，不在提交成功后丢失通知。

会话只保存 URI 引用，不保存照片像素或 RAW 副本；持久格式最多 500 个槽位及 2MiB JSON。超限拒绝保存并保留上次记录，当前编辑和原片不会被截断或删除。未知会话版本、未知字段和损坏数据保留并提示；不可读会话不会阻断正常图库列表。多变体会话与虚拟副本仍待后续实现。

## 性能与访问边界

完整摘要仅在用户核对、重新关联，以及从图库打开已核对记录时读取，按 64KiB 流式处理；不进入滑杆、胶片切换、普通保存或图库滚动。校验期间不持有编辑存储的全局锁，读完后再做事务核对。列表继续使用有界小缩略图，不为 RAW 列表启动完整解码。

文件选择器结果会尝试持久读取授权；不提供持久权限时显示临时访问提示。授权成功不保证云端永远在线或用户之后不会撤销权限。

本批没有将所有导入、导出、缓存和渲染统一成新的源版本合同。正常导入仍兼容先前 URI 规则，尚未校验的历史记录不会自动补完整摘要；编辑器打开后原片被外部改写的统一检测仍待完成。首次校验不是历史真实性证明，重新关联也不自动识别重新编码、修改 EXIF 或仅视觉相同的照片。

图像引擎、RAW 解码、像素算法、尺寸、位深和编码质量不因本批改变。真机、厂商云端、长期授权及原有 50MP/IIR/超宽图限制继续保留。

## 验证与剩余项

验证证据保存在 `.tmp/source-recovery/`，最终汇总为 `verification.json`，包括分构建的升级、存储、真实交互、性能和原生截图。文件选择器自动化拦截系统结果并经过真实 ActivityResult 回调，不冒充实际厂商云端验收。

已通过首轮真实旧 APK 覆盖安装，确认 v1 数据的 ID、revision、亮度及裁剪保留，v2 校验与工作台关闭重开后可读。专项覆盖相同尺寸不同内容拒绝、无校验凭据拒绝、已登记目标拒绝、过期 revision 拒绝、事务回滚、旧地址迟到写保护、工作台重映射、离线及空勾选、未来会话只读保留和流式取消。

真实 Activity 重建后恢复当前照片、顺序和导出勾选通过；图库菜单、首次说明、取消、错误原片、正确移动原片、后续编辑和撤销重做通过。重新关联保持另一张当前照片的 native 底图，不触发额外显影。最终测试还覆盖旧地址再次导入时的后台异常保护、取消后离开并刷新、选择器返回与刷新竞争、跨 ViewModel 迟到保存和容量超限保护。

最终生产原生库测试宿主通过 14 组回归及一组真实进程恢复，共 26 条记录，另有大字体、平板和横屏三组布局验证。重新关联事务在 `SOURCE_RELINKED` 和 `SOURCE_RELINK_COMMITTED` 两处实际终止进程，重开后分别完整回滚或完整提交，资产和编辑版本无重复。前序候选版 21 组回归与首轮旧 APK 覆盖安装证据单独保留，不混称最终版本的覆盖安装验证。

最终 120 次保存中位数 0.754178ms，p95 3.808223ms。上一批同类模拟器采样为 1.0672ms 和 3.0731ms；中位数和长尾存在运行波动，不宣称真机零开销或固定提速。Z6II 输出 6064×4040、16 位 TIFF，146992152 字节，完整 SHA256 仍为 `62f1d58c709a4bc694ca93f8d552954320f921260fc64dd4c013bf4461926f3f`。本轮首导 9069ms、缓存导出 2597ms，仅为模拟器采样。

测试中曾出现模拟器 `RenderThread` 持续占用一核、引擎及测试线程等待和 `SurfaceSyncGroup` 超时；普通重启后系统服务 `DEAD_OBJECT`，保留数据冷启动才恢复。随后发现安装包的 native 库和 Manifest 与预定宿主不同，Kotlin dex 和资源相同，具体改变原因未证实。该轮结果未作为最终验收：重新安装预定宿主，测试前后及最终屏幕配置前后拉包核对 SHA256 均为 `dc7095df138675743677161a2f3fcca2165aa12348753f28fbae77fab8b1847d`，再完成整组回归。中断输出、线程诊断、包差异和复测证据均保留，未改 GPU 设置或降低图像质量。

正式安装包为 `app/release/v0.1.5-f07-source-recovery/Theia-v0.1.5-source-recovery.apk`，大小 55453433 字节，SHA256 `ed7698b0c557ef1798fb8cab5ec87ec970637a9b8d6ebd136ad24cad787e4667`。版本仍为 0.1.5，versionCode 6。原证书 V1、V2、V3 签名通过；6 项原生库、94 项引擎资源和正式 Manifest 与上一批逐字节相同。最终屏幕设置恢复为 1080×2400、420dpi、字体 1.0。

独立视觉复核对最终构建的 19 张截图给出 `ship`：正常手机的工作台、恢复结果、原片菜单、校验说明、已核对、拒绝和重新关联状态，以及大字体、平板、横屏的四种关键状态。之前将底部部分离屏行视为内容裁切的判断，经拥有布局的代码与新截图复核后更正为原生列表的正常视口裁切，未为此修改生产布局；旧评审保留在证据目录。该结论只涵盖界面，不代表真机性能验收。

独立设计文档核对确认本批继续使用既有字体、颜色、轮廓和 Material 控件，没有新增全局视觉规则，`DESIGN.md` 和 `.impeccable/design.json` 保持原样。测试结束后已正常启动应用首页，屏幕与字体设置保持默认；未将刻意终止进程的恢复测试计作正常启动崩溃。
