# T05：八色 HSL 与自然饱和度

本阶段扩展 T04 的同一成片后期合同。入口为调色页的“色彩混合”：自然饱和度、八个带文字的色点，以及所选颜色的色相／饱和度／明亮度。每色与全部色彩可分别复位；延续圆体、炭灰、琥珀和原有照片预览。窄栏按四列两行展示，宽栏八列；选择不依赖色点颜色，保留无障碍标签、选中语义和系统字号。

## 算法与来源

依据本地 SpektraLab 原型提交 `1952c63537ec576d24422f1065b12495631346a5` 的 `app/SpektraLab/Sources/Engine/Layer2Kernel.swift`（l2Vibrance／l2Hsl）及 `Sources/Model/Adjustments.swift`。将该 GPL-3.0-or-later 代码的色彩数学适配为 Kotlin 参考与 Android JNI/C++ 条带实现；没有移植 Metal，也没有修改共享引擎、材料模型或旧影调公式。

自然饱和度范围为 −100…100，以 max/min 色差估算饱和度，增益为 max(1+v×(1−sat),0)，围绕 Rec.709 编码空间亮度轴调整。它减少对高饱和色的影响，不另外宣称检测人脸或保护肤色。

HSL 使用原型亮度正交的色度平面，而非调用平台 HSV。色区中心为红 0°、橙 30°、黄 60°、绿 120°、青 180°、蓝 240°、紫 270°、洋红 300°。相邻中心之间以 smoothstep 混合；红色跨 360° 环绕。三项范围均为 −100…100，色相满量程为 ±30°，饱和度缩放 0…2，明亮度满量程为 ×0.5…1.5，并按色度减弱对近灰色的影响。

执行顺序：已有白平衡／影调／饱和度 → 自然饱和度 → HSL → 已有色彩平衡 → T04 曲线 → 暗角。新操作为中性时跳过，旧 sidecar 不增加默认字段；沿用已有工作空间、灰点与最终量化。

## 存储和交互

不可变 ColorAdjustments 保存版本 1 与八个 HslBand，写入 color_adjustments 对象。有效值必须有限且在范围内；无法读取的未来版本、畸形或原始非对象数据保留原记录并提示，导出拒绝静默忽略，用户明确复位后才清除，并可撤销。

加入现有快照、历史、复制、每图 sidecar 与缓存身份。拖动更新现有冲印底图，松手提交一次历史／保存；拖动取消、离开工具或切换照片恢复该手势的起点。选择其他颜色不触发显影；后期撤销／重做继续复用底图。

## 处理与验证范围

预览、JPEG／PNG 和 16 位 TIFF 共用同一原生 CPU 后期条带。每次最多 32 行，不增加整帧 float 缓冲；默认无新效果时保留旧快速路径。DI 不包含成片后期。没有新增 Vulkan 调色内核，不将本阶段当成 HDR 或专业色域升级。

专项入口为 audit=color 与 audit=color-raw。验收核对数学边界、中性兼容、灰色与高饱和色、红色环绕、八色往返和复制、未来数据保留、原生与参考误差、三种编码、实际滑杆完成／取消、历史和保存；24MP 原片与多尺寸 UI 的最终结果见[开发进度](../development-progress.md)。

真机驱动、持续性能、大图全局峰值和超宽图条带边界继续单列验收，不能以模拟器数学通过代替。通道混合、色轮、分组编辑预设与图库迁移依然属于后续工作。
