# F07 第一批：照片图库与正式编辑存储

日期：2026-11-13。范围：F07 的默认编辑存储和最小照片图库；F07 整体仍为进行中。此批不包含相册、评级、色标、虚拟副本界面或发布操作。

## 用户可见的变化

- 首页增加“照片图库”入口。图库按最近保存排序，点击照片可恢复上次的编辑参数并继续显影。
- 列表保留照片原比例缩略图，提供导入、刷新、分页和空状态。沿用 Theia 的深色、暖白、琥珀色及圆角样式。
- 原片移动、授权失效或编辑版本不兼容时，保留照片记录和调整，并给出提示；不会以默认参数覆盖旧记录。
- 保存失败时给出明确提示，可重试保存或先留在当前编辑页面。
- 旧版照片在重新打开同一个来源 URI 后进入新图库；启动时不扫描整机照片，也不猜测孤立旧记录对应的原片。

## 存储边界

正式数据库为应用私有目录下的 `photo-library/saved-photos.db`，独立于 T06 沙盒原型。保留 `EditStore` 作为编辑器、智能分析、预设批量应用和导出读取的统一入口。正式库只包含资产和默认编辑版本；T06 的多变体及会话原型未直接升级为生产功能。

资产采用精确 URI 身份，保存稳定的 asset ID、default variant ID、递增 revision 和更新时间。不同提供方、不同 URI 或相同媒体编号不会按名称、内容摘要或编号自动合并。源内容变更检测、完整指纹重定位和可持久多变体会话仍待后续实现。

首次读取旧 sidecar 时，先复制完整原始 JSON 到 `legacy-backups` 并校验，再在事务中认领旧键、建立资产与编辑记录。已认领的 `media-42` 不允许被另一个 URI 再次继承。新库成为唯一保存位置，旧 sidecar 保持原样。旧版未完成批次日志在实际采用未登记 URI 前恢复。

批量保存先核对全部目标的预期 JSON，再在同一事务写入；目标已变化时整批拒绝。智能建议使用 `saveIfAbsent`，迟到的分析不能覆盖已有手动设置。相同参数的普通保存不增加 revision 或改变排序。

损坏 JSON、已知字段类型错误、不支持的顶层版本及更高数据库版本均保留原数据并拒绝覆盖。自定义数据库错误处理器保留损坏数据库文件，避免 Android 默认处理器删除文件。初次采用保留原始未知字段；分组复制延续 F06 的未知字段合并策略。

## 性能与画质约束

图库元数据在 IO 调度器读取，每页 60 条；缩略图最多两路并发，解码边长上限 384 像素。缓存以 12 张为预算，当前列表仍在组合中的行额外保留，离屏后按预算淘汰，防止大屏一屏超过 12 行时留下占位图；保留量随视口而非全部图库增长。RAW 列表只读取内嵌预览，不启动完整 RAW 解码或胶片显影。缩略图尺寸仅用于列表，不改变编辑和导出。

保存保留同步事务和崩溃恢复语义。优化仅合并重复查询、复用精确 JSON 的校验结果和有限数量 URI 的标识；不降低数据库持久性。120 次保存测得：

| 构建 | 中位数 | p95 |
| --- | ---: | ---: |
| F06 对照 | 0.8301ms | 1.2923ms |
| 首轮 F07 候选版 | 2.8914ms | 5.9293ms |
| 第一轮保存优化 | 1.5284ms | 4.1645ms |
| 保存快路径优化候选版 | 1.1101ms | 3.1626ms |
| 最终包，模拟器重启后 | 1.0672ms | 3.0731ms |

首轮发现回退后未直接交付。最终仍存在约 0.24ms 的中位数差异，不宣称零开销；保留全部冷启动和长尾样本，没有通过降低持久性或图像质量换速度。全部为同一模拟器采样，不代表手机性能。

本批不修改 native 图像处理、RAW AHD 解码、分辨率、位深、编码质量、shader 或引擎素材。最终 APK 的六项 native 库、94 项引擎素材及正式 Manifest 与 F06 逐字节一致，原证书 V1、V2、V3 签名校验通过。既有 50MP 超时、IIR 内存与执行容量、超宽图片及 ARM 真机限制继续保留。

## 验证证据

证据保存在忽略目录 `.tmp/saved-photos/`，最终汇总为 `verification.json`。正式 APK 与原签名保持兼容，测试宿主使用同一生产 native 库和 debug 可检测代码。测试宿主不作为用户安装包交付。

已完成的候选版验证包括真实 F06 覆盖安装、25 组功能回归、正式库事务边界故障注入、真实进程终止恢复及三类屏幕配置。最终保存快路径候选版另通过 25 组回归；随后只修改图库可见缩略图的缓存淘汰，最终包的针对性验收和三类屏幕配置单独记录，不混用构建证据。

反复测试时，无变化保存保留原排序，导致缺源夹具落到第一页之外，首次横屏测试因此失败；夹具改为先做实际编辑后恢复测试值，并等待有效缩略图后拍照。等待又暴露了平板一屏超过 12 张时可见图片被淘汰的问题，已修复为保留当前组合中的行。原始失败、构建与复测记录全部保留。

最终包首轮复测在编辑工具中遇到系统“Pixel Launcher 无响应”弹窗，遮挡了测试目标。失败截图及事件日志记录 `com.google.android.apps.nexuslauncher` 的焦点输入超时，保留数据重启模拟器后使用同一生产 APK 重跑；系统无响应根因未最终确认，不能据此证明真机无类似问题。

具体检查：旧亮度及裁剪恢复、稳定身份、后续新编辑不再写旧文件、媒体编号碰撞、过期批次全拒绝、迟到建议保护、损坏及未来数据保留、133 条分页、无变化保存、真实首页导航、缺源保留、继续编辑、撤销重做，以及浏览图库不启动渲染。真实终止分别发生在迁移事务提交前后，重开后回滚或继续采用，二次重放不重复资产或编辑版本。

模拟器导入、导出和 RAW 回归沿用原完整图像摘要；最终构建结果、耗时及界面复核结论见验证汇总和开发进度。

最终包验收包括 14 组针对性回归和一组真实进程终止恢复，共 25 条功能记录，另有三类屏幕配置及最后一次同包图库完整交互复测。覆盖存储、图库、预设、参数边界、调度、胶片切换、智能显影、导入、导出、编码和真实 RAW。保存快路径候选版的 25 组完整回归作为前序证据，最后生产变更仅涉及图库缩略图淘汰。

Z6II 样本输出 6064×4040、16 位 TIFF，共 146992152 字节，完整 SHA256 为 `62f1d58c709a4bc694ca93f8d552954320f921260fc64dd4c013bf4461926f3f`，与既有结果相同。其他旧 RAW 缓存与完整导出摘要继续通过。

安装包：`app/release/v0.1.5-f07-saved-photos/Theia-v0.1.5-saved-photos.apk`。版本 0.1.5，versionCode 6，大小 55409195 字节，SHA256 为 `f0b13867f3922531d939eb53eaa5d197a21836a2302f94ced2aab5579ff20fcf`。测试宿主已从模拟器拉回核对摘要，屏幕恢复为 1080×2400、420dpi、字体 1.0。没有提交、推送或创建 GitHub Release。

独立界面审核结论为 `ship`，范围为本批首页入口及图库的 11 张有效截图：正常手机首页、空状态、列表、缺源提示和返回列表，以及大字体、平板和横屏的列表与缺源状态。没有必须修改的界面问题；长文件名在大字体下占用较多高度被记录为可选优化。该结论不代表真机性能或未拍摄功能的验收。

独立设计文档核对确认本批复用既有颜色、圆润字体、轮廓和原生组件，没有新增全局视觉规则，因此保留 `DESIGN.md` 和 `.impeccable/design.json`。既有文档目录不完整及较旧时间戳已记录，不作为本批顺带修复内容。审核与文档核对报告保存在本批证据目录。
