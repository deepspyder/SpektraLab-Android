# 第三批：成片曲线

日期：2026-11-11。对应实施方案 T04，属于 F04 的曲线部分。HSL、自然饱和度、通道混合和色轮不属于本次完成范围，统一见[开发进度](development-progress.md)。

## 行为

调色页新增可折叠曲线区，提供 RGB、明度和 R/G/B 五个通道。点击曲线加点、拖动调节；控制点不能交叉，端点 x 固定，最多 12 点。可删除内部点、复位当前通道或全部曲线；输入/输出微调按需展开。新文字进入 strings.xml，继续现有圆体、炭灰表面与琥珀选择风格。

拖动期间只更新已有冲印底图的后期；松手提交一次编辑历史与每图保存。父参数滚动不能抢走曲线手势；系统取消、多指介入或离开曲线时恢复手势起始值。滑杆取消也恢复，原图按住对比继续独立工作。仅后期历史的撤销/重做不重新显影。

无障碍曲线动作可添加控制点及选择前/后一个点，再通过滑杆调整。五通道选择保留选中语义、触摸区和横向溢出滚动，照片不因新工具强制缩小或改变比例。

## 数学与存储

不可变 ToneCurve 保存归一化控制点，x 严格有序，使用带切线限制的分段 Hermite 插值；每条曲线的切线只生成一次。ToneCurves 序列化版本为 1，表为五行各 1025 个 float32 样本；顺序为 rgb/luma/red/green/blue，执行则为明度、RGB、分通道。

曲线在原有色彩平衡之后、原有暗角之前。延续已有编码空间与灰点，不借此改变历史色彩合同，也不是胶片前 Decode 曲线。明度通过同一 RGB 增益处理，近黑零值按已有上游约定处理；RGB 与分通道再查表。

完全默认曲线不写额外旧 sidecar 字段；有控制点但仍中性的拓扑会保存，并能撤销。有效曲线加入复制/快照/历史与缓存身份，改变曲线会保守地使原有输出缓存失效。原始曲线数据无法读取时保留原 JSON，显示提示；用户明确复位后才替换，正常导出拒绝忽略该错误继续保存。

## 原生处理与输出

新曲线有效时，预览、JPEG/PNG 与 TIFF 都调用相同的 JNI/C++ 条带数学；不增加 Kotlin 全帧曲线循环。每次最多 32 行，不为曲线再创建全帧 float 图。原生实现复用 legacy 影调顺序，使用关闭浮点收缩的编译选项，按相同表、坐标和暗角查表输出。它是 CPU 原生处理，本次没有增加或宣称 GPU 曲线内核。

没有有效曲线时完全保留旧处理/快速量化路径。DI 本来不包含成片后期，继续不应用曲线。Display P3 预览沿用现有显示转换；不把本阶段宣传为新增 Adobe RGB/ProPhoto/HDR 支持。

预览按条带检查协程取消，过期任务及时结束并回收没有发布的 Bitmap；不重新解码原图或改变原始位深、颗粒和光晕。

## 验证

专项入口为 instrumentation 的 audit=curves，测试模型中性/线性/单调边界、五通道往返、未来数据保留、复制与几何保持，以及原生与 Kotlin 参考误差、TIFF 样本、sRGB/P3 预览。实际页面注入触摸，检查完成与取消、保存、撤销/重做、不重新显影、通道切换、复位与三种实际导出。

本阶段保留失败证据：首轮复位查找未滚动；新增真实取消测试又发现父滚动抢占/取消提交问题，改为明确的触摸所有权与 UP/CANCEL 分离，未删除原断言。最终构建、专项、多尺寸截图与全回归结果由本批验证清单记录，不能用先前成功或仅编译通过替代。

2026-11-11 的最终构建已通过 Debug、androidTest 和签名 Release，同一构建的 21 组回归、172 条记录全部通过。API 37 x86_64 模拟器使用 Release 原生库配合测试签名；手机大字体（1.3 倍）、平板和横屏均完成真实曲线操作专项及截图核对。短横屏的调色栏合并重复的文件、材料和面板标题，保留照片预览与导航，为曲线操作提供更多高度。

24MP Nikon Z 6 II NEF 的带曲线全尺寸导出为 6064×4040、146,992,152 字节 TIFF。首次与缓存命中后的文件完全一致，SHA-256 为 `8316f8bb09d07fab6d4fd0dae8ed25e67aa4c09180ced6989ac943df632f8890`，并与中性曲线基线不同。该轮耗时为 9660ms / 2733ms，关闭颗粒和眩光；这是一次模拟器功能样本，不是手机性能保证。

小米 17 Pro 和其他 GPU 真机未连接，实际驱动、峰值与持续交互性能仍待验证。原生曲线每次调用有 32 行、1,048,576 像素的保护上限；当前固定条带尚未适配宽度超过 32768 像素的超宽图，不能据此宣称任意尺寸均已验收。共享引擎和 LibRaw 与第二批验收基线一致。
