# F05 第二批：整体与分区色轮

日期：2026-11-12。本批承接已验证的通道混合，推进色轮功能；未提交或发布。

## 使用方式

打开照片 → 调色 → 色轮。选择整体、阴影、中间调或高光，拖动圆盘选择色相和着色强度。中心为零强度，越靠近边缘着色越强；三个精调滑杆分别控制色相、着色强度和分区明度。支持单项还原、当前分区还原与全部还原。默认折叠，沿用现有照片优先布局、圆体、炭灰和琥珀控件。

一次按下至松手只形成一个历史事务。系统取消、切图或退出控件时恢复已提交参数。精调滑杆保留 Material 的无障碍范围和键盘操作；圆盘不替代精调入口。单独选择色相但强度为零时，记住角度且不改变画面。

## 版本与数学合同

- `color_wheels` version 1 保存 master、shadows、midtones、highlights 四个分区。色相为 0 至 360 度，强度为 0 至 100，明度为 -100 至 100，严格拒绝非有限数、错误类型和越界数据。
- 新色轮使用上游 ColorZone 的三相余弦 RGB 偏移，强度系数 0.25；明度以 0.25 换算为增益。分区权重仍根据既有中灰 0.4614 的 tonePosition 计算，阴影为 `(1-ls)^2`，高光为 `ls^2`，中间调为剩余权重。
- 处理顺序为既有影调、HSL、通道混合、旧 temp/tint 加法、新色轮加法和明度增益、末端 clamp、曲线。保留旧六个 temp/tint 参数；本批未将原调色空间切换到新的颜色模型。
- 全部色轮中性时完全跳过新计算，默认 sidecar 不新增字段；只保存非默认角度时仍然走中性计算路径。旧文件和中性输出保持兼容。
- 未知版本及损坏数据原样保留。导出前要求用户明确还原，避免输出时静默遗漏未知效果；撤销可恢复原始数据。
- RGB 偏移与增益只在参数对象变化时准备；逐像素不分配新对象。预览和三种导出共用 Grade，native 使用最多 32 行的现有条带，不增加整张浮点图或 GPU plane。
- JNI 方法签名不变，颜色 uniforms 扩展到 53 项，同时兼容既有 26 项和 36 项布局。
- 快照、每图 sidecar、撤销重做、复制和批量导出接入新参数。复制仍保留目标照片构图；草稿手势不进入其他操作的保存快照。导出先取消未提交的色轮手势。

## 验证与证据

同一生产 APK 完成 26 组、188 条功能回归，另完成色轮截图复拍、13 个预览计时场景（中性对照与 12 项参数）、大字体手机、平板和横屏三种配置。完整证据：`.tmp/color-wheels/verification.json`。

- 四分区代数 35,604 样本通过；组合独立标量参考包含旧影调、HSL、通道混合、旧 temp/tint 和曲线。native 最大误差为 3.5762787e-7，小于 4e-6 门槛。
- 原 26 项和 36 项 native 参数布局逐位相同；196,608 个中性色轮的既有标量 Float 样本完全相同。sRGB、Display P3 预览和 16 位 TIFF 与参考一致。
- 真实圆盘与滑杆拖动、系统取消、12 项分区精调、色相单独保存、还原、撤销重做、手势草稿隔离、切图、每图保存和复制通过。连续 24 次输入后的最终画面与最新参数逐像素一致，胶片底图身份保持。
- 实际单张和批量 PNG 整图像素与参考相同；实际 JPEG 和 TIFF、旧裁剪和暗角、元数据开关、RAW 取消、导入选择、智能显影及原有效果回归通过。

首轮完整回归遇到模拟器 System has crashed，保留全部失败与系统日志：系统 UI 和电话进程报告 DeadSystemException，Google 服务随后反复 native 崩溃。根因未最终证实。保留 userdata 冷启动后，在同一生产包上重跑中断用例。额外截图导致的离屏圆盘定位和旧暗角测试的首屏假设分别修正为真实滚动定位，未放宽原功能断言。
