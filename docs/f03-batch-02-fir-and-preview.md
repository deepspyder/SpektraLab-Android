# F03 第二批：有限核分带验证与整图所有权优化

日期：2026-11-12。基于提交0c96041继续开发。本批未提交或发布，版本仍为0.1.5(6)。

## 本批交付

### 默认启用：释放已完成使用的胶片前处理图

此前run_film保留前处理结果cur，又将它按const引用传给film_segment。即使阶段链早已进入其他节点，外层局部对象仍持有完整图面。Android一次性导出现在将其所有权移动到阶段链，按原节点和原顺序计算，完成最后一次读取后引用即可释放。普通预览与非一次性路径保持原有语义。
这减少的是活跃图面的重叠，不是减少输出尺寸或改变像素公式。全尺寸输出、颗粒、光晕、色彩空间和精度保持。

### 默认启用：用已发布请求身份判断预览是否还需续算

旧逻辑只检查renderJob是否仍active；画面已经发布但协程还在收尾时，导出会错误记录为未完成，结束后又渲染一次。新增publishedRenderRequest，发布native结果或由后期工作者发布同一底图时标记已完成请求。导出只续算真正尚未发布的native请求，仍保持最后一次调参和后期编辑不丢失。
新增确定性边界测试将已发布状态与仍active的收尾工作固定下来，要求导出后lastResult和Bitmap身份保持；原有真正待处理拍摄和后期的成功/取消恢复用例继续通过。

同一份独立androidTest测试包搭配0c96041原生产代码复验，新增已发布请求用例明确失败，其余7项原边界用例通过；搭配最终修复代码则全部通过。这个前后对照保留在published-boundary-before.txt与delivery/editing-boundaries.txt，完成后模拟器恢复为修复版。

### 研发路径：精确有限核高斯FIR分带，默认关闭

- 每带带上完整垂直邻域，保留真实边缘反射；仍使用原垂直FIR和水平FIR内核，不更改权重、累加、Float次序或最后量化。
- 工作带根据行宽控制，中心输出最多256行，工作目标16MiB；有累加时传入对应带的完整累加数据。
- 每带之间检查取消，失败不公布部分输出；递归调用用作用域隔离，IIR和全局统计不被替换成有限邻域近似。
- 使用debug.theia.export_fir_bands临时开启，仅研发诊断，无普通用户开关；默认关闭。原因见性能结果，不能把局部收益包装为整个导出更快。
- tools/build_export_fir_audit.py编译独立Android验证程序，该测试程序不进入APK。

## 数值与内存验证

独立NDK验证覆盖200个场景、68,823,384个Float样本、1648个显式分带；原图1行、窄图、奇数尺寸、首尾边缘、部分末带、不同带高、负值/高光、累加和混合FIR/IIR均逐位相等。自动大图门槛实际触发10带，且带间取消及正常路径隔离通过。
| 独立FIR图面测试 | 临时缓冲高水位 |
| --- | ---: |
| 整图FIR | 131.89 MiB |
| 分带FIR | 88.19 MiB |

第一次24MP两轮交错测量中，直接开启FIR分带的全流水线峰值仍为1682.2MiB；渲染时间增加约29%—36%。因此没有作为默认优化交付，数值正确并不等于产品性能收益成立，所有原始测量保留。
之后改为默认关闭实验分带、启用前处理图所有权转移，交错两轮核对真实24MP RAW如下。

| 24MP场景 | 原版临时池高水位 | 本批默认路径 | 原版渲染中位数 | 本批渲染中位数 |
| --- | ---: | ---: | ---: | ---: |
| 颗粒和眩光关闭 | 1682.2 MiB | 1401.8 MiB | 1080.6 ms | 1099.1 ms |
| 全部默认效果 | 1682.2 MiB | 1401.8 MiB | 1169.2 ms | 1144.9 ms |

GPU临时池高水位不等于进程总峰值，不包含全部持久源图、CPU结果、暂存和驱动内存。计时来自同一模拟器、同Release优化级别的两轮样本，不能承诺手机速度或将解码采样变化归因本批。
比较基线为0c96041的原生库；原版和本批均已包含前一批一次性导出。与最初未优化包的比较必须另外计算，不能叠加不同时期的耗时。所有8次24MP完整测试TIFF哈希、尺寸和字节数保持。
