# 第二批：优先调度与正式导出缓存

日期：2026-11-11。承接[首批渲染基础](render-foundation.md)，对应 F01/F02 的继续实现。整体进度见[开发核对清单](development-progress.md)。

## 1. 调度与状态

EngineTaskQueue 保留跨挂起点的事务所有权，等待队列新增优先级：清理、交互、用户导出、预取。同级按任务 ID 先后执行；优先任务最多连续越过较老等待项 8 次，之后执行最老项。当前运行的同步 native/GPU 调用不被强行抢占。

等待和恢复时检查取消；取消项从队列删除，异常后释放所有权。进度查询与 native 取消仍走现有线程安全旁路，不排在自己等待完成的任务后面。StateFlow 提供 active、waiting、completed/cancelled/failed，Task 带 ID、kind 和 priority，不记录照片路径。

本批没有新进度页面，也没有把全部缩略图和智能分析迁入一个全局任务体系。完整任务成本模型与状态机仍待补齐。

## 2. 内存压力准入

RenderAdmission 在真实导出解码/渲染和命中后的编码前检查系统 low-memory 标志及可用内存阈值。系统压力下以明确错误结束尝试，保留原始尺寸和画质选项；不缩图、不关效果、不无限重试。

这不是 GPU 容量预测器。可用 RAM 不能证明 Vulkan 分配一定成功，也没有降低 F03 全局阶段的活跃峰值。设备成本模型与小米真机校准仍待完成。

## 3. 正式缓存范围

单张与逐张批量导出可复用无损 RGBA16 冲印结果；JPEG、PNG 和 TIFF 共用 Rgba16Source 行接口，再按每次冻结配方编码并公开。缓存的是处理底图，不是上次文件，不会复用旧文件的元数据选择。

首期准入：颗粒关闭、眩光关闭、片边关闭、日期后背关闭；本地 file URI 或 authority 为 media 且可寻址的普通文件；源图/构建/资源/镜头/编辑身份明确并满足空间预算。其他效果保留原参数。

默认颗粒和眩光状态不变。当前引擎缺少 Android 可完整控制的显式随机 seed 合同，因此随机任务绕过缓存，不以固定噪声换命中率。云端、pipe 和其他 provider 不为探测缓存额外获取原片。DI、软打样和高清预览仍走既有路径。

## 4. 身份与失效

每次可准入请求流式 SHA-256 读取原片，不能只用 URI、名字、大小或 mtime。写缓存前再次核对内容，避免源图变化后挂到旧 key；对外部任意并发改写的完整原片快照/锁定合同仍待资产层实现。

MediaStore 来源通过授权描述符的副本读取，不通过 /proc 路径重新打开。补充测试曾发现该来源与本地相同字节的身份不一致；修正读取方式后，URI/文件身份对照及完整缓存专项通过，保留了失败与通过日志。

资源指纹来自实际交给引擎的 filesDir/engine/resources 全部文件（含 shader/profile）、镜头配置和实际 APK 内容；引擎 build info、安装更新时间也进入构建身份。同一进程复用已计算资源指纹，不改现有启动资源同步策略。

key 包含请求长边（0=原始）、输入解码合同、输出空间、镜头开关、完整编辑快照和版本。查缓存前不伪造输出宽高：用明确请求尺寸作为身份，实际宽高来自校验后的文件头。片边/自动日期暂排除，避免猜测扩展画布。

目前保守包含所有编辑字段，后期改变也会 miss；以后省略字段必须验证阶段分类。同一空间可以跨容器复用，sRGB/P3 不混用。

## 5. 存储与失败

应用进程只有一个 ExportRenderCache 所有者，避免多个 ViewModel 的租约管理器互相覆盖。CRC、16 位行读写、临时文件原子发布与租约继续保留；完整校验和读取可取消，关闭句柄但不删除有效条目。

已发布缓存总额首期最多 512 MiB，写入还要求当前可用空间至少为两倍结果大小加 256 MiB，给暂存与输出留余量。超预算、宽度超格式范围、空间不足只跳过写缓存，不限制原图导出。这是保守初始策略，尚非真机最优数值。

缓存 I/O、损坏、权限、版本或状态失败回到重算/正常保存；取消继续传播。缓存写失败不阻止已有正确结果保存。正常输出或 MediaStore 错误不被缓存层吞掉。单张 hit 不重开正确的预览会话，真实解码/render 后才恢复会话。批量保持串行与每图 EXIF 独立。

## 6. 测试与证据口径

Instrumentation audit 入口：render-scheduling、export-cache、render-foundation、export-cache-raw。最后一项要求 external files 的 functional-audit/perf-z6ii.NEF 存在，不允许缺原片时跳过却报通过。

小图专项实际走解码、引擎、正式缓存及 MediaStore，覆盖 miss/write/hit、完整 TIFF 相同、JPEG/PNG/批量复用、损坏重算、原图/参数失效及随机/云端绕过。大 RAW 使用流式摘要，不把整份 TIFF 读到 ART 数组。

首轮 Debug 小图约 973 ms / 416 ms，最终构建结果另行保存。这是单次模拟器样本，不是手机或 RAW 大图的加速承诺。命中跳过重算不同于首次渲染峰值优化；不宣称所有 GPU 卡死已修复。F01/F02 的剩余条件与未开发功能继续记录在进度清单。
