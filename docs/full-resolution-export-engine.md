# Android 全尺寸导出：引擎资源生命周期优化

日期：2026-11-12。基于Theia v0.1.5继续优化，此次提交包含Android源码、验证结果和剩余项，没有发布新Release。

**未解决：连续回归后的50MP真实应用JPEG导出仍在渲染阶段超过240秒，随后模拟器出现系统native异常。原生50MP测试TIFF通过不能替代这一失败；冷启动后没有完成该用例复测，50MP应用TIFF也未执行。**

## 结论与真实构建来源

app/src/main/cpp/engine只有接入说明。实际SPEKTRA_ENGINE_DIR在CMake缓存中指向SpektraLab-Windows的engine，构建时将源码编译进Android自己的libspektralab.so。没有跨电脑调用、共享运行进程或网络渲染，共用目录本身不增加手机运行耗时。
真正需要适配的是桌面会话缓存策略、多个整图GPU中间结果的重叠、同步Vulkan执行，以及RAW解码、镜头校正和CPU编码。复制一份源码目录或创建更多引擎实例不能自动解决这些成本；更多实例还可能增加内存重叠。

## 已实现的改动

1. Android增加renderExportOnce，只用于单张与批量成片导出。普通预览、原有renderForExport、软打样和DI保留自身语义。
2. DIR读取完log曝光图后立即释放这份不再使用的整图引用，避免它继续与颗粒阶段重叠。
3. 一次性导出直接持有当前负片完成冲印，不再为马上销毁的会话额外分配并复制一份持久负片。
4. 最终RGBA16打包和CPU读回前，释放已无用途的源图、负片及层级引用；结果独立持有CPU像素，会话在返回时关闭。即使后续节点返回别名，rgb的引用计数仍保留必要存储。
5. 使用线程局部RAII作用域隔离策略，失败和取消时恢复；下一次正常打开仍缓存负片。Android CMake适配生成专用源码，并对上游锚点做失败检查，不修改桌面检出。
6. 增加默认关闭的详细节点诊断，通过debug.theia.export_timings临时开启；日常导出不支付该诊断成本。
7. 针对本轮捕获的Java堆OOM，scheduleRender增加明确处理，保留现有显示帧并提示重新打开，避免未捕获错误直接终止应用。这个防护不代表消除了所有内存峰值。

没有修改RAW解码质量、AHD、分辨率、胶片和相纸模型、默认颗粒和光晕、输出位深、JPEG质量或调色数学。旧engine目录说明已更正为实际行为。

## 全尺寸相机原片对照

测试来自API37 x86_64模拟器，Goldfish/GFXStream，使用实际Release优化级别的原生库。基线测试包的原生库与保存的v0.1.5交付包逐字节相同，并确认其应用dex没有新的一次性入口。修复包同样核对Release原生库身份。

| 场景 | 原版GPU临时池高水位 | 优化后GPU临时池高水位 | 减少 | 完整TIFF输出 |
| --- | ---: | ---: | ---: | --- |
| 24MP NEF，颗粒和眩光关闭 | 1682.2 MiB | 1682.2 MiB | 0.0 MiB | 尺寸与完整SHA一致 |
| 24MP NEF，全部默认效果 | 1962.5 MiB | 1682.2 MiB | 280.4 MiB | 尺寸与完整SHA一致 |
| 50MP DNG，全部默认效果 | 4032.0 MiB | 3456.0 MiB | 576.0 MiB | 尺寸与完整SHA一致 |

**临时池高水位不是进程总峰值。** 它不包括持久源图、CPU结果、传输暂存和GPU驱动等。24MP默认效果减少约280MiB，50MP减少576MiB，但后者仍有约3.38GiB的临时活跃高水位，不能因此宣称所有手机都不会卡顿。关闭颗粒的场景高水位未降，也如实保留。
新入口返回时导出会话已关闭，持久源图和负片计数为0；旧入口在返回时保留会话。因此返回时驻留差异是明确的生命周期改变，不把它当作整个流水线峰值降低的数值。

| 场景 | 阶段 | 原版耗时 | 优化后耗时 |
| --- | --- | ---: | ---: |
| 24MP默认效果 | RAW解码 | 2352.8 ms | 2178.8 ms |
| 24MP默认效果 | 镜头校正 | 1573.9 ms | 1554.1 ms |
| 24MP默认效果 | 引擎输入 | 884.2 ms | 910.1 ms |
| 24MP默认效果 | 全尺寸渲染至结果可用 | 1251.1 ms | 1335.4 ms |
| 24MP默认效果 | TIFF编码 | 636.3 ms | 723.2 ms |
| 24MP默认效果 | 测试事务总计 | 7127.9 ms | 7132.4 ms |
| 50MP默认效果 | RAW解码 | 5372.7 ms | 5305.4 ms |
| 50MP默认效果 | 镜头校正 | 0.0 ms | 0.3 ms |
| 50MP默认效果 | 引擎输入 | 1388.1 ms | 1377.5 ms |
| 50MP默认效果 | 全尺寸渲染至结果可用 | 8090.9 ms | 6457.4 ms |

| 50MP默认效果 | 测试事务总计 | 16965.4 ms | 14894.0 ms |

以上是同模拟器每场景一次前后样本，不是稳定加速比例，更不是手机时延承诺。新入口耗时包含会话关闭；旧入口的关闭发生在随后编码之前。RAW解码和镜头校正未改，二者采样变化不能归因此次优化。
分阶段引擎测试写出不含ICC的测试TIFF，实际应用的TIFF仍包含原有ICC；两种文件各自和对应基线比较，不混用摘要。

## 正确性、取消与回归

- 新增35组完整U16输出对照，覆盖全部胶片家族、兼容相纸、旋转裁剪、片边日期和相同初始随机状态的颗粒，全部通过。
- 真实运行中的一次性渲染可取消，结束后会话释放；后续普通渲染重新建立负片缓存，作用域未泄漏。
- 原有单张、批量、DI、软打样、高清预览和恢复编辑会话链路完成回归；原生结果在会话关闭后仍可读。
- 最终同一构建23组、181条记录通过。组名：export-once, changed-params, export-actions, export, editing-boundaries, export-cache-raw, curves-raw, color-raw, export-cache, render-foundation, render-scheduling, raw-input-access, raw-cancellation, export-encoding, nef-import, export-memory, batch-selection, editing-feedback, native, effect-baselines, stock-interaction, import-selection, smart-develop。
- 24MP中性、曲线和HSL实际应用全尺寸TIFF的完整SHA保持原基线；94项引擎资源逐字节不变。arm64-v8a与x86_64均编译通过，实际运行来自模拟器。
- 首次快捷导出回归曾因Java堆接近192MiB而在继续编辑时崩溃，日志保留。原代码测试包和优化包的同用例复测均通过；最终构建额外补上OOM处理并重跑，不能把这一失败删掉后描述为首轮全绿。
